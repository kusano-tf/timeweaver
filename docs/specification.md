# Timeweaver 仕様書

## 目的

Timeweaver は、タイムライン情報や年表のようなデータを可視化・編集する、バックエンド不要の Web アプリケーションである。

初期版は汎用タイムライン編集ツールとして実装する。プロジェクト管理専用、歴史年表専用、創作設定専用には寄せず、期間アイテム・時点アイテム・依存関係・タグ・表示状態を JSON ファイルとして入出力できることを重視する。

## 技術方針

- React / TypeScript で実装する。
- ビルド基盤は Vite を使う。
- パッケージ管理は pnpm を使う。
- lint / format は Biome を使う。
- 日付計算は date-fns を使う。
- JSON の構造・型・形式検証は Zod を使う。
- 状態管理は React の `useReducer` と Context を基本にする。
- 依存伝播、検証、日付計算などのドメインロジックは純粋関数として分離する。
- タイムライン本体は SVG 中心で描画する。

## 初期版スコープ

初期版では次の機能を必須とする。

- JSON インポート / エクスポート
- Zod による厳格な JSON 検証
- 期間アイテムと時点アイテムの表示
- アイテムの詳細編集
- アイテムのコピー
- 手動レーン配置
- タグの作成・削除・編集・並べ替え・フィルタ
- レーンの作成・削除・並べ替え
- 表示粒度の切り替え
- Finish-to-Start 依存関係の表示・編集
- アイテムのドラッグ移動
- 依存先方向への自動伝播
- 現在表示中のタイムライン範囲の PNG 出力
- サンプルタイムラインの初期表示
- `docs/` と `.agents/` のドキュメント整備

初期版では次の機能は必須としない。

- Undo / Redo
- バー端ドラッグによる期間リサイズ
- 依存線のドラッグ作成
- 範囲選択によるアイテム作成
- UI E2E テスト
- 数千件以上のアイテムに向けた仮想化や高度な描画最適化
- 複数ビュー保存
- 自動保存
- リロード後の作業データ自動復元

## 日時

日時は秒精度まで保持する。

保存形式はタイムゾーンなしのローカル日時文字列とする。

例:

```json
"2026-07-13T09:30:00"
```

曖昧日付は扱わない。ユーザーが確定日時に補完してから入力する前提とする。

期間アイテムは開始を含み、終了を含まない半開区間 `[start, end)` とする。`end` は必ず `start` より後でなければならない。

UI での日時編集はブラウザ標準の `datetime-local` 入力を使い、分単位で編集する。保存時は秒を `00` として、従来通り `YYYY-MM-DDTHH:mm:ss` 形式を維持する。

## アイテム

時点アイテムと期間アイテムは同じ `items` 配列に格納し、`type` で分岐する。

- 時点アイテム: `type: "instant"` と `at` を持つ。
- 期間アイテム: `type: "duration"` と `start` / `end` を持つ。

共通属性として、ID、タイトル、説明、レーン、タグ、色などを持てる。

## 依存関係

初期版の依存関係は Finish-to-Start のみを実装する。

基本式:

```text
to.start = from.end + lagSeconds
```

`lagSeconds` は正・ゼロ・負を許可する。

依存関係は循環禁止とする。依存追加時と JSON インポート時に循環を検出し、循環する依存は受け入れない。

初期版の自動伝播は依存先方向のみとする。`fromId -> toId` の向きでのみ後続アイテムを移動する。

依存伝播で後続アイテムが動く場合、期間アイテムは期間の長さを維持して `start` と `end` を同じ差分で移動する。時点アイテムは `at` を同じ差分で移動する。

ユーザーが先行アイテムの終了日時を詳細パネルで変更した場合も、`lagSeconds` を維持するために後続アイテムを同じ差分で移動する。期間アイテムの開始日時だけを変更し、終了日時が変わらない場合は後続へ伝播しない。時点アイテムが先行アイテムの場合は、`at` の変更を基準に後続へ伝播する。

ユーザーが後続アイテムを手動移動した場合は、依存関係を維持したまま `lagSeconds` を再計算する。

将来の拡張として、Start-to-Start、Finish-to-Finish、Start-to-Finish、逆方向伝播、双方向伝播に対応できる余地を残す。

## レーン

初期版の縦方向配置は手動レーン方式とする。

JSON は `lanes` 配列を持ち、各アイテムが `laneId` で所属レーンを参照する。

同一レーン内で表示上重なるアイテムは、レーン内のサブ行へ自動的に上下配置する。サブ行は表示時のレイアウトであり、JSON には保存しない。

レーンは UI から追加・削除できる。アイテムが配置されているレーンは削除できない。

レーン管理一覧ではドラッグハンドルによる並べ替えができる。並べ替え後は `order` を `0` 始まりの連番へ正規化し、タイムライン本体の縦方向表示にも即時反映する。

レーン管理は通常の編集画面からは隠し、画面右上の設定ボタンから開く設定パネル内で行う。基本画面ではアイテム追加とタイムライン編集に集中できる構成とする。

## タグ

タグはフィルタ用途と色情報を持つ。

タグは UI から追加・削除・並べ替えできる。タグを削除した場合、そのタグ ID は各アイテムの `tagIds` と表示フィルタから取り除く。削除タグを `colorTagId` で参照しているアイテムは `colorTagId` を `null` に戻す。

タグ名とタグ色は追加後も編集できる。タグ管理は通常の編集画面からは隠し、画面右上の設定ボタンから開く設定パネル内で行う。

タグ管理一覧ではドラッグハンドルによる並べ替えができる。並べ替え後は `order` を `0` 始まりの連番へ正規化する。タグ管理の並べ替えでは、各アイテムの `tagIds` 順序は変更しない。

表示色の優先順位は次の通り。

1. アイテムの `color`
2. `colorTagId` で指定したタグの `color`
3. `tagIds` の先頭タグの `color`
4. デフォルト色

`colorTagId` は、アイテムに付いているタグの中から自動色に使うタグを指定する。`null` の場合は `tagIds` の先頭タグの色を使う。タグ追加時は `colorTagId` を自動変更しない。タグ解除やタグ削除で `colorTagId` が参照不能になった場合は `null` に戻す。

タグフィルタは OR / any とする。選択したタグのどれか 1 つでも付いているアイテムを表示する。

タグ未設定アイテムは、タグフィルタが空のときだけ表示する。タグが 1 つでも選択されているときは非表示にする。

タグは UI 上ではピル型の見た目で表示する。詳細パネルでは、設定済みタグをピル一覧として表示し、既存タグを検索して追加できる。詳細パネルから新規タグは作成しない。

## 表示

初期版の表示設定は単一の `view` とする。

表示粒度は次を扱う。

- `year`
- `month`
- `day`
- `hour`

データは秒精度まで保持するが、分・秒はタイムラインヘッダーの初期表示粒度には含めない。

## 編集

タイムライン上の直接操作は、初期版では次に絞る。

- アイテム選択
- ドラッグによる日時移動
- ドラッグによるレーン変更

細かい編集は詳細パネルで行う。

- タイトル
- 説明
- 日時
- タグ
- 色
- 依存関係
- レーン

詳細パネルからアイテムをコピーできる。コピー時はアイテム本体のみを複製し、新しい ID とコピー用タイトルを付与する。依存関係は自動コピーしない。

タグ・レーンの管理操作は詳細パネルではなく設定パネルに集約する。詳細パネルでは、アイテムに既存タグを付け外しする操作のみを扱う。

## 保存モデル

初期版では自動保存しない。

ブラウザ内の作業状態は即時更新されるが、JSON ファイルへの永続化はユーザーがエクスポートしたときだけ行う。

`localStorage` などによるリロード後の作業データ自動復元は行わない。

未エクスポート変更がある場合は、離脱確認を表示する。

## インポート

JSON インポートは厳格検証する。

不正データがある場合は、ファイル全体を読み込まず、検証エラー一覧を表示する。

部分的な読み込みや暗黙の補正は行わない。

## 画像出力

画像出力は、現在表示中のタイムライン範囲を PNG として出力する。

出力対象:

- タイムライン本体
- 表示粒度
- タグフィルタ
- レーン
- 依存線
- 色

出力対象外:

- 画面外にスクロールしている領域
- 編集パネル
- ツールバー

## 性能目標

初期版は数百アイテムを快適に扱えることを目標とする。目安は 500 件前後とする。

数千件以上の大規模データ向け最適化は初期版では必須としない。

## テスト

初期版では Vitest によるドメインロジックの単体テストを必須とする。

重点対象:

- 期間アイテムと時点アイテムの Zod 検証
- 不正日時の拒否
- `[start, end)` の `end > start` 検証
- 存在しない ID 参照の拒否
- 循環依存の検出
- Finish-to-Start 依存の後続伝播
- 後続手動移動時の `lagSeconds` 再計算
- タグ OR フィルタ

UI E2E テストは初期版では後回しにする。

## UI 言語

初期版の画面表示は日本語とする。

コード、API、JSON キーは英語とする。
