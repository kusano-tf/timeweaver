# Timeweaver 実装ガイド

## 目的

このドキュメントは、Timeweaver を実装・変更するコーディングエージェント向けのガイドである。

実装時は `docs/specification.md` と `docs/json-format.md` を常に同期すること。

## 技術スタック

- React
- TypeScript
- Vite
- pnpm
- Biome
- date-fns
- Zod
- Vitest

## ドメインロジック

依存伝播、日時計算、JSON 検証、タグフィルタなどは UI コンポーネントに埋め込まず、`src/domain/` 配下の純粋関数として実装する。

重点領域:

- `src/domain/schema`: Zod スキーマと JSON パース。
- `src/domain/datetime`: タイムゾーンなし日時文字列と date-fns 変換。
- `src/domain/dependencies`: Finish-to-Start 依存、循環検出、後続伝播、`lagSeconds` 再計算。
- `src/domain/filtering`: タグ OR フィルタ。

## 状態管理

初期版の状態管理は React の `useReducer` と Context を使う。

Reducer はタイムラインドキュメントへの変更を扱う。

想定アクション:

- インポート成功時のドキュメント置き換え
- アイテム追加・編集・削除
- アイテムコピー
- アイテム移動
- 依存伝播
- `lagSeconds` 再計算
- タグ・レーン・表示設定の更新
- 表示範囲のズーム / パン
- タグ・レーンの並べ替え
- タグ・空レーンの削除
- 未エクスポート変更フラグの更新

Undo / Redo は初期版の必須機能ではない。

## UI

画面表示文言は日本語にする。

コード、API、JSON キーは英語にする。

タイムライン本体は SVG 中心で描画する。フォーム、ツールバー、詳細パネルなどは通常の React DOM で実装する。

同一レーン内で表示上重なるアイテムは、SVG レイアウト時にサブ行へ自動配置する。サブ行番号は派生表示状態であり、JSON へ保存しない。

タイムラインの表示範囲は `view.visibleRange` で管理する。`null` は表示対象アイテム全体の自動表示を表し、ズーム / パン後は `start` / `end` を持つ日時範囲として保存する。既存 JSON で欠けている場合はインポート時に `null` として補完する。

ズームボタンは表示範囲の中央基準で 2 倍 / 1/2 倍にする。`Ctrl` + ホイールはカーソル位置の時刻を基準にズームし、`Shift` + ホイールは倍率を変えず左右へパンする。通常ホイールは縦スクロールとして残す。

タグは UI から追加・削除・並べ替えできる。削除時は各アイテムの `tagIds` と `view.visibleTagIds` から該当 ID を取り除き、該当 ID を参照する `colorTagId` は `null` に戻す。

タグ管理とレーン管理の一覧は `dnd-kit` でドラッグハンドルによる並べ替えに対応する。キーボード操作にも対応する。並べ替え後は対象配列の `order` を `0` 始まりの連番へ正規化する。タグ管理の並べ替えでは各アイテムの `tagIds` 順序は変更しない。

アイテム色の優先順位は、`item.color`、`item.colorTagId` で指定したタグ色、`item.tagIds[0]` のタグ色、デフォルト色の順とする。`colorTagId` は `string | null` の必須フィールドで、指定時は同じアイテムの `tagIds` に含まれていなければならない。

レーンは UI から追加・削除できる。ただし、アイテムが配置されているレーンは削除しない。先にアイテムを別レーンへ移動させる。

アイテムコピーは詳細パネルから実行する。コピー時はアイテム本体のみを複製し、依存関係はコピーしない。

初期版の直接操作は次に限定する。

- アイテム選択
- ドラッグによる日時移動
- ドラッグによるレーン変更

バー端ドラッグによる期間リサイズ、依存線のドラッグ作成、範囲選択作成は初期版の必須機能ではない。

## JSON と検証

JSON 形式は `docs/json-format.md` を正とする。

インポートは厳格検証する。エラーがあればファイル全体を読み込まない。

Zod で構造・型・日時形式を検証し、次のような横断的整合性は追加ロジックで検証する。

- ID 重複
- 存在しない ID 参照
- 依存関係の循環
- 期間アイテムの `end > start`

## 日時

保存形式はタイムゾーンなしの秒精度文字列 `YYYY-MM-DDTHH:mm:ss` とする。

実装ではこの文字列を正とし、計算時だけローカル `Date` に変換する。UTC 変換やタイムゾーン付き日時として扱わない。

## 依存関係

初期版は Finish-to-Start のみ実装する。

```text
to.start = from.end + lagSeconds
```

`lagSeconds` は正・ゼロ・負を許可する。

自動伝播は依存先方向のみとする。

後続アイテムを移動する場合、期間アイテムは期間の長さを維持して丸ごと移動し、時点アイテムは `at` を移動する。

ユーザーが後続アイテムを手動移動した場合は、該当する依存関係の `lagSeconds` を再計算する。

詳細パネルの先行依存では `lagSeconds` を編集できる。編集時は対象依存を優先し、依存先アイテムを `from.end + lagSeconds` へ前後どちらにも移動する。複数の先行依存がある場合、他の incoming `lagSeconds` は移動後の配置に合わせて再計算する。依存先の後続は、既存の依存伝播と同様に制約違反時だけ後ろへ移動する。

タイムライン下部には開閉可能な依存ビューを置く。依存ビューは JSON へ保存しない UI 状態として開閉し、全依存を先行アイテム開始日時、後続アイテム開始日時、依存 ID 順で表示する。依存ビューまたは SVG の依存線から依存を選択した場合、依存先アイテムも選択し、依存ビュー行、SVG 依存線、詳細パネルの先行依存行を強調する。

詳細パネルは `App` のローカル UI 状態として表示 / 非表示を切り替える。初期状態は表示とし、非表示時も右端に再表示レールを残す。アイテムや依存を選択しても詳細パネルは自動では開かない。

依存関係は循環禁止とする。

## テスト

Vitest でドメインロジックの単体テストを必須とする。

少なくとも次をテストする。

- Zod 検証
- 不正日時の拒否
- 期間アイテムの `end > start`
- 存在しない ID 参照の拒否
- 循環依存の検出
- Finish-to-Start 依存の後続伝播
- 後続手動移動時の `lagSeconds` 再計算
- タグ OR フィルタ

UI E2E は初期版では後回しでよい。

## ドキュメント同期ルール

実装で仕様が変わった場合は、同じ変更で次を更新する。

- `docs/specification.md`
- `docs/json-format.md`
- `.agents/implementation-guide.md`

JSON 形式、依存伝播、保存モデル、日時形式、初期版スコープに影響する変更は必ずドキュメントも更新する。

ロードマップ項目を実装する場合は、必要に応じて `docs/roadmap.md` から該当項目を更新し、確定仕様は `docs/specification.md` または `docs/json-format.md` へ反映する。
